# Candidate Screening — Narrative-Text Forensics Challenge

Fifteen candidates were generated across the open domains. Every candidate
is grounded in a genuine public dataset whose landing page and license were
verified by direct HTTP fetch on 2026-07-09 (no URL, DOI, or license below
is invented). Candidates were screened against the Eris gates: clear
license, novelty, resistance to rule-based/GBM shortcuts, external
reconstruction risk, and feasibility of deterministic preparation/grading
within the Kaggle Python Docker image.

**Selected candidate: #1 — Interleaved narrative disentanglement + tamper
forensics over real public-domain prose.**

---

## 1. Interleaved Narrative Disentanglement & Tamper Forensics — SELECTED

- **Open domain:** NLP.
- **Source dataset:** Standardized Project Gutenberg Corpus (SPGC) metadata
  catalogue, used to select genuine English-language public-domain
  narrative texts; full book bodies fetched from the official Project
  Gutenberg mirror (each text independently public domain in the US).
- **Source URL:** https://zenodo.org/records/2422561 (SPGC metadata/catalog)
  and https://gutenberg.pglaf.org/ (official PG high-speed mirror, listed at
  https://www.gutenberg.org/MIRRORS.ALL; `robots.txt` permits automated
  file fetches — only `/ebooks/search` is disallowed).
- **License:** CC BY 4.0 (SPGC catalog) — https://creativecommons.org/licenses/by/4.0/;
  individual book texts are public domain in the United States (Project
  Gutenberg License terms, stated in each file's boilerplate header).
- **DOI:** 10.5281/zenodo.2422561
- **Proposed transformation:** Take real, contiguous paragraph runs from
  pairs of unrelated real books (true original authorial order preserved
  within each run). Deterministically **interleave** the two streams using
  an undisclosed, seeded run-length schedule, then apply a small,
  undisclosed-rate **local tamper** operation (adjacent same-stream swap).
  Participants see only the shuffled-looking combined sequence of paragraph
  texts; they never see which book contributed which paragraph, the
  original book identity, or the interleaving/tamper parameters.
- **Hidden structure to infer:** narrative/stylistic coherence (lexical
  recurrence, discourse continuity, character/pronoun consistency) that
  distinguishes which of two hidden streams each paragraph belongs to, its
  true relative position within that stream, and whether it was locally
  tampered.
- **Heterogeneous targets:** stream label (binary), intra-stream rank
  (ranking/permutation), tamper flag (binary) — three heterogeneous target
  types with a same-arena consistency constraint (predicted intra-stream
  ranks must form a valid permutation per predicted stream).
- **Expected novelty:** 5/5 — this is not a standard sentence-ordering
  benchmark: the ground truth is not "the real book's order" but a
  *composite* of real order plus an undisclosed synthetic interleave/tamper
  schedule, so finding the source books online does not reveal the answer.
- **Likely difficulty:** hard — requires real text representation
  learning (coherence/adjacency modeling), not keyword classification.
- **Major rejection risks & mitigations:** (a) *shortcut via web lookup of
  famous novels* — mitigated by sampling from a large, deliberately
  mid-obscurity band (30–2,500 historical download count, i.e. neither
  blockbuster classics nor unreadable ephemera) across 100+ distinct book
  pairs, and by the fact that even a solver who finds both source books
  cannot recover the interleave schedule or tamper points, which are
  generated by undisclosed code, not by either book; (b) *plain
  bag-of-words shortcut* — same-broad-subject pairs are deliberately
  included to force genuine coherence modeling rather than topic
  classification; (c) leakage — book IDs/titles/authors are never included
  in public files, only anonymized per-arena segment slots.

## 2. Direct Sentence-Order Reconstruction (single book, no interleave)

- **Domain:** NLP. **Source:** same SPGC/Gutenberg pipeline.
- **Transformation:** shuffle paragraphs of one real chapter; recover order.
- **Novelty:** 2/5. **Rejected:** the ground truth *is* the real book's
  order — a solver can find the source text online and read off the
  answer directly. No undisclosed transformation blocks this shortcut,
  unlike candidate #1.

## 3. Strawberry Ripeness Object Detection

- **Domain:** Object Detection. **Source:** Strawberry dataset for object
  detection, Zenodo, https://zenodo.org/records/6126677, CC BY 4.0,
  DOI 10.5281/zenodo.6126677 (YOLO-format boxes for ripe/unripe berries and
  peduncles, ~1.5 GB).
- **Novelty:** 2/5. **Rejected:** standard bounding-box detection is
  explicitly listed as an anti-pattern ("standard object detection only");
  the 1.5 GB payload is also heavy for a fast, reproducible pipeline.

## 4. Canola Seedling Growth-Stage Detection

- **Domain:** Object Detection. **Source:** Canola seedling object
  detection dataset, Zenodo, https://zenodo.org/records/11055599,
  CC BY 4.0.
- **Novelty:** 2/5. **Rejected:** same anti-pattern as #3 — plain detection,
  no heterogeneous targets or consistency constraints without heavy
  re-engineering, and CV training inside the validation budget for this
  task is higher-risk than a text/tabular pipeline.

## 5. Smart Contract Vulnerability Multi-Label Classification

- **Domain:** From Scratch. **Source:** Smart contract vulnerability
  dataset, Zenodo, https://zenodo.org/records/16910242, CC BY 4.0,
  DOI 10.5281/zenodo.16910242.
- **Novelty:** 2/5. **Rejected:** collapses to standard multi-label
  classification, solvable by a bag-of-tokens + gradient boosting baseline;
  little room for the required heterogeneous/consistency structure without
  fabricating labels.

## 6. DIVE Multi-Label Smart Contract Vulnerability Dataset

- **Domain:** From Scratch. **Source:** DIVE dataset, Zenodo,
  https://zenodo.org/records/18519253, CC BY 4.0, DOI 10.5281/zenodo.18519253.
- **Novelty:** 2/5. **Rejected:** provenance concern — constructed by
  scraping the Etherscan API; the CC BY declaration covers the curators'
  packaging but the underlying on-chain source data's redistribution terms
  are not independently confirmed on the record page. Also same
  classification-shortcut issue as #5.

## 7. Slither Audited Smart Contracts (Hugging Face)

- **Domain:** From Scratch. **Source:** `mwritescode/slither-audited-smart-contracts`,
  Hugging Face Datasets, license tag `mit` (verified via the HF datasets
  API `license:mit` tag), credential-free download via `datasets` library
  or direct HTTP.
- **Novelty:** 2/5. **Rejected:** vulnerability-label prediction from
  Solidity source is a well-trodden benchmark shape (label classification);
  doesn't naturally yield the required heterogeneous/consistency/stratified
  structure without inventing unsupported labels.

## 8. Bilingual Spanish Labor-Law QA (RAG)

- **Domain:** RAG. **Source:** Bilingual Dataset for Information Retrieval
  and Question Answering over the Spanish Workers' Statute, Zenodo,
  https://zenodo.org/records/4256718, CC BY 4.0, DOI 10.5281/zenodo.4256718
  (150 real Q&A pairs over a real legal document).
- **Novelty:** 3/5. **Rejected:** only 150 Q&A pairs — too small to build
  stratified buckets and a robust held-out test split; expanding supervision
  would require LLM-generated questions, which the guide disallows in the
  submitted dataset.

## 9. Movie Reviews Dataset (Cornell-derived)

- **Domain:** NLP. **Source:** Movie Reviews Dataset, Zenodo,
  https://zenodo.org/records/14203180, CC BY 4.0, DOI 10.5281/zenodo.14203180
  (17,165 professional critic reviews, 1940s–2020s).
- **Novelty:** 2/5. **Rejected:** natural fit is sentiment/rating
  regression from review text — explicitly listed as an anti-pattern
  ("generic sentiment/topic classification"); would need heavy
  reformulation to escape that shape.

## 12. Two-Stream Dialogue Disentanglement from Real Transcripts

- **Domain:** NLP. **Source:** considered building from public IRC/chat
  transcript corpora with permissive licenses.
- **Novelty:** 4/5 in concept. **Rejected:** could not find a
  credential-free, clearly-licensed real multi-party chat transcript corpus
  of adequate size and quality within the time available (the well-known
  academic disentanglement corpora carry mixed or unclear redistribution
  terms) — candidate #1 achieves the same "disentanglement" structure with
  cleanly verified public-domain text instead.

## 13. Legal-Document Cross-Reference Consistency Auditing

- **Domain:** RAG. **Source:** would require a large, genuinely public,
  cleanly licensed corpus of cross-referencing legal/statutory documents.
- **Novelty:** 4/5 in concept. **Rejected:** no dataset found during search
  that combines (a) a clear permissive license, (b) credential-free bulk
  access, and (c) enough real cross-reference density to support the
  planned consistency-constraint scoring, within the time budget for this
  task.

## 14. Prompt-Engineering Robustness on a Fixed Local Classifier

- **Domain:** Prompt Engineering. **Rejected outright:** any prompt-facing
  task needs an LLM in the loop at solve time; the guide requires
  `solution.ipynb` to run offline in the Kaggle Python Docker image using
  only `pandas`/`numpy`/`scikit-learn`/`xgboost`/`lightgbm`/`tensorflow`/`pytorch`,
  with no LLM calls and no LLM outputs in the dataset — this domain is
  structurally incompatible with those constraints for a from-scratch,
  reproducible grader.

## 15. LLM-Output Quality Evaluation Rubric

- **Domain:** LLM Evaluation. **Rejected outright:** this domain's natural
  data shape is (prompt, model output, quality label), but the guide
  explicitly forbids using LLM outputs as part of the submitted dataset —
  there is no way to construct a genuine LLM-evaluation task here without
  violating that rule.

---

## Rejection-log summary of domains not pursued

- **Fine-Tuning:** every credential-free route considered (fine-tuning a
  small pretrained checkpoint) either required internet access at solve
  time to fetch weights (violates the offline Kaggle Docker constraint) or
  reduced to a standard classification fine-tune with no room for the
  required heterogeneous/consistency structure within the time budget.
- **Prompt Engineering / LLM Evaluation:** structurally blocked by the
  guide's "no LLM outputs in the dataset, no LLM calls in the solution"
  rules (see #14, #15).

## Why #1 wins

Candidate #1 is the only concept that simultaneously (a) sits on a
verified, clearly-licensed, credential-free source (SPGC catalog CC BY 4.0
plus per-book Project Gutenberg public-domain texts), (b) blocks the
"just find the source and read the answer" shortcut structurally — the
graded target is a function of undisclosed generation code, not of either
source book alone — mirroring the same defense that worked in the
"unfluke" task, (c) yields genuinely heterogeneous targets
(stream/rank/tamper) with a natural permutation-validity consistency
constraint, and (d) supports real stratified buckets (arena length ×
source-genre similarity) that meaningfully vary task difficulty, rewarding
real representation learning over real English prose instead of
keyword-level shortcuts.
